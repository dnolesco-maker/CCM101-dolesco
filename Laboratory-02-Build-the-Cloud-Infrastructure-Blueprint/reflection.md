# Mission Reflection

Through the activities in this laboratory, I gained insight into the interactions among different cloud infrastructure components in supporting cloud computing. Of all the components, the compute resources would be the most important since they are what give the processing power required for cloud computing. Without compute resources, the rest of the components like storage and networking would not have much function because without a computer to process them, no work would be done.

Additionally, I learned the role played by Linux in cloud computing through the investigation of the KillerCoda Linux environment using the `lscpu`, `free -h`, `lsblk`, `df -hT`, `hostname`, and `hostname -I` commands which were used to get information on the server's CPU, memory, storage, filesystem, hostname, and network respectively.

Also, documentation prior to deployment of infrastructure was an important lesson I gained through this laboratory. Technical documentation captures resource details, configuration details, findings, and designs that help the engineer to have the full picture about the intended environment and helps him or her to spot any potential issues before deploying it. It also helps to make the technical information more understandable to other engineers in the team.

In this laboratory, I acquired several skills which include investigating the Linux server, identifying the components of cloud infrastructure, comparing the major cloud providers, creating documentation in Markdown language, managing the GitHub repository and cloud architecture design. By doing the comparison of the three main providers, i.e., AWS, Microsoft Azure and Google Cloud Platform, I understood that although their names are different, they provide similar infrastructure functions.

Finally, by doing this mission, my GitHub portfolio was enhanced with a laboratory folder containing the technical reports, cloud components documentation, providers comparison, screenshots and mission reflection. Additionally, I got practice on committing code with meaning and maintaining proper evidence for every checkpoint.
