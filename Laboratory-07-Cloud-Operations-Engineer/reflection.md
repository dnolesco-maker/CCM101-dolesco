# Mission 7: Reflection

Checking host resources is important even if containers are running perfectly because containers depend on the host machine's CPU, memory, and disk space. Even if an application works properly, limited resources can eventually affect its performance. Monitoring the host helps identify possible resource problems before they cause service interruptions.

The `docker logs` command helps investigate problems by displaying messages generated by a container. If a user cannot log in, I would check the logs for errors, failed requests, or application messages related to the problem. These details can help identify the possible cause and guide further troubleshooting.

Logs and metrics are both important for monitoring, but they provide different types of information. Logs contain records of events, requests, and errors, while metrics provide numerical measurements of resource usage and performance, such as CPU percentage and memory consumption. In this laboratory, I used `docker logs` to inspect HTTP responses and errors, while `docker stats` helped me monitor the container's resource usage.

Enterprises can use monitoring tools such as Prometheus and Grafana to monitor thousands of containers. Prometheus collects and stores metrics, while Grafana presents monitoring data through dashboards and visualizations. These tools help operations teams identify performance issues, track resource usage, and respond to potential problems across their infrastructure.

This laboratory improved my ability to troubleshoot Linux environments by teaching me how to use commands to inspect system resources and investigate application behavior. I learned to check memory and disk space, deploy an Nginx container, test HTTP responses using `curl`, examine application logs, and monitor container metrics. These activities helped me understand the importance of systematic monitoring and troubleshooting in maintaining reliable application services.
