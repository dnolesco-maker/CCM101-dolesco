# Mission 9 Reflection: The Cloud Automation Engineer

Cloud automation is important because managing hundreds of cloud servers manually takes a lot of time and effort. Using Bash scripts and Cron allows administrators to automate repetitive tasks, such as backups, and perform them on a schedule. Automation also helps make operations more consistent and reduces the chance of human error.

However, automation can also be dangerous when a script contains mistakes. For example, a destructive command scheduled to run on 1,000 servers could delete important files or damage systems before anyone notices. This is why scripts should be reviewed and tested in a safe environment before being deployed across multiple servers. Administrators should also use proper permissions and monitoring.

A Bash script and a Docker Compose YAML file serve different purposes. A Bash script executes shell commands to automate tasks, such as creating compressed backups and scheduling operations. Docker Compose uses a YAML configuration file to define and manage services, networks, and volumes for an application. In Mission 6, Docker Compose helped manage a multi-container application, while this mission focused on automating system tasks with Bash and Cron.

Throughout Laboratories 1 to 9, my understanding of cloud computing developed from learning basic cloud concepts to practicing infrastructure management, containers, data storage, and automation. These activities helped me understand that cloud computing involves more than accessing online resources. It also requires configuring systems, managing data, securing resources, and maintaining reliable services.

My favorite cloud role is the Cloud-Native Engineer because I am interested in building and managing applications using modern technologies. Learning about containers, automation, and cloud infrastructure gives me a foundation for this career path. I want to continue improving my technical skills through hands-on projects and practical experience.
